How vme-insight-plugin works

The plugin adds a vme-insight tab to the host, VM, instance and cluster pages of HPE Morpheus, and an optional home-dashboard widget. Morpheus only serves the tab: a frame and a link. The browser then loads the dashboard directly from vme-insight, so the Morpheus appliance never connects to vme-insight, and the plugin holds no passwords or data. Tabs match the right object because vme-insight's collector stores Morpheus's own ids.

vme-insight-plugin in Morpheus
  • Tab providers for servers (hosts and VMs), instances and clusters

  • Launcher (optional): a vme-insight link on every page
  • Theme loader (global UI component): adds vme-insight-theme.js to every page, only with Match each user's Morpheus theme
  • show(): tabs appear only when the Grafana URL is set, and, if enabled, for roles with the vme-insight permission

https front end Caddy · :443 or :3443
  • Port: 443 on the appliance (https on by default), 3443 with Docker Compose
  • TLS: the browser must already trust the certificate. A frame can't show a warning, so an untrusted one leaves the tab blank.
  • Allowlist (HTTPS_ALLOW): only admin networks; others get 403
  • Reverse proxy to Grafana
Grafana 11.5
  • Anonymous Viewer (GRAFANA_ANONYMOUS): read-only, no sign-in inside the frame
  • Embedding allowed (GRAFANA_ALLOW_EMBEDDING)
  • GRAFANA_ROOT_URL = the plugin's Grafana URL, so links stay on one address
  • Dashboards filtered by the Morpheus id in the URL
  • Theme from the URL; HPE backgrounds: #222222 dark, white light
TimescaleDB · Prometheus History, inventory and lifecycle (SQL); exporter metrics (PromQL). Stored with Morpheus's own host, VM and cluster ids.
collector Polls the Morpheus API every minute with a read-only account. Separate from the plugin; doesn't involve the browser.
1An admin opens a host, VM, instance or cluster page in Morpheus.
2The plugin returns the tab (an iframe and a link) and a frame-src policy that lets the Morpheus page show it.
3The browser loads the dashboard itself, from vme-insight over https, e.g. /d/vme-hosts?var-host=42, with the theme added.
4The front end checks the certificate is trusted and the network is allowed, then passes the request to Grafana.
5Grafana, as a read-only anonymous Viewer, queries the stored data for that Morpheus id and draws the dashboard.

Needed in vme-insight first

https front endAppliance: on by default (port 443). Docker: docker compose --profile https up -d https. Morpheus pages are https, and browsers block http frames inside them.
CertificateFrom a CA your browsers already trust, or a make-cert.sh host certificate imported on each admin machine after checking its fingerprint
Who can reach itHTTPS_ALLOW = the networks your Morpheus admins use
No sign-inGRAFANA_ANONYMOUS=true (read-only Viewer), GRAFANA_ALLOW_EMBEDDING=true
One addressGRAFANA_ROOT_URL = the plugin's Grafana URL (by IP? also HTTPS_DEFAULT_SNI)
On the appliance, sudo vme-insight-setup asks for these. Step by step: docs/VME-PLUGIN.md. vme-insight works without the plugin; the plugin needs vme-insight.

If the tab doesn't show the dashboard

No vme-insight tabGrafana URL not set, or Require permission on and the role lacks it
Blank tab, "might be having issues"This browser doesn't trust the certificate (on Windows: imported by double-click, as an intermediate)
"This content is blocked"Page policy: check the URL setting is saved (and its port), reload; plugin 0.1.1 or later
Forbidden (403)This network isn't in HTTPS_ALLOW
Grafana sign-in pageAnonymous viewing off, or Grafana not restarted
ERR_SSL_PROTOCOL_ERRORBrowsing by IP: set HTTPS_DEFAULT_SNI, or use the name
Links jump to another addressPlugin URL and GRAFANA_ROOT_URL differ
Theme doesn't match MorpheusGrafana theme isn't set to match, or the theme script didn't load (reload the page)
